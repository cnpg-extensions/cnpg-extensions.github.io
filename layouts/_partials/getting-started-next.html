3. Add an extension to your cluster

Browse the catalog and open an extension’s documentation. Follow its Cluster example to enable the extension image, including any preload settings or required dependencies. Keep your existing instance and storage configuration, and reference the installed catalog:

imageCatalogRef:
  apiGroup: postgresql.cnpg.io
  kind: ClusterImageCatalog
  name: postgresql-minimal-trixie
  major: 18

For a new installation, first follow the CloudNativePG quick start to install the operator and create a database cluster.

4. Enable it in a database

Making an extension image available to the cluster does not install it into every database. You can enable an extension declaratively with a CloudNativePG Database resource, or run CREATE EXTENSION through SQL. The extension’s README provides its exact SQL name and any setup requirements.

Platform teams can make extension containers available by default while letting users enable only the extensions their databases need. For extensions that normally require superuser privileges, pgextwlist allows administrators to approve a selection for non-superuser installation.

Check: verify the installed extension with \dx in psql, and keep the update alerts configured in step 1. After container updates, use the extension’s supported SQL upgrade path where needed.
